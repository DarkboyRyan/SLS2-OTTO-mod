# v0.5.0 新设计卡牌验证

2026-09-30。基于本机《杀戮尖塔2》v0.107.1、BaseLib 3.4.7；用 MegaDot 4.5.1.m.14 构建，使用游戏自带引擎和真实 API 验证。

## 结果

**中文和英文环境各451项引擎断言通过。** 测试使用正式出牌包装器、真实伤害命令、选择器接口、保留清理与原版选牌归还方法。验收源码为 `tools/confirmed_cards_probe.cs.txt`；两次成功标记见 `confirmed-cards-verification.log`。

- 注册63张卡：60张设计卡与3张水果。奖励池20普通、25罕见、12稀有，另有3基础牌。逐张验证基础/升级描述格式和卡图资源；OTTO仍为91生命、91金币、11张初始牌及棍亩。
- 啊，哥我错了的8/11格挡和1/2虚弱只施加给所选目标；兄弟你动啊0费抽1张并积攒20/30古神值，形态中仍抽牌且不积攒，打出消耗。
- 欧西给普通状态9/12伤害，古神状态对同一目标两段，未加其他增益时合计36/48。
- 哎呀米诺只允许选择弃牌堆的古神牌，不选普通牌或消耗堆；空候选时仍给予6/9格挡。
- 猪逼吧在无伙伴/伙伴入狱时仍正常攻击；山泥若在场时只行动一次，强化与小强化相加，覆盖7治疗和全体4中毒。其他伙伴不跟随行动。
- 调用游戏自身的手牌清理方法验证保留折扣：手牌每次保留减1，抽牌堆和弃牌堆不减；不同实体独立；最低0；打出只移除自己的折扣，不擦除外部设置的5费。
- 千早爱音基础抽2/升级抽3；允许跳过整理，原有其他牌相对顺序保持。边缘资格用出牌前快照，技能自身抽牌不会改变资格。
- 额外使用真实Godot卡牌容器和原版 `OnSelectModeSourceFinished` 归还逻辑，验证选中牌归还后画面顺序与模型同为最左，回调只执行一次。测试只替代本地手牌实例定位，没有替换原版归还逻辑。
- 本回合易拉罐触发数与牛魔整场出牌数分离；中间出牌、自动出牌只计原有出罐记录；敌人和队友回合不清零自己的计数，牛魔重置不影响本回合连招。不同玩家各自记录。
- 丰川翔子从边缘打出可以触发自己；叠加至2层不刷新已用机会，下个自己回合首次触发回2能量；不追溯能力生效前的触发，队友回合不刷新。
- 三角初华复制升级状态、运行时获得的易拉罐和战斗内修改；只允许非X费攻击牌，犹如幻翳可选。源卡不变，复制牌置于最右侧、当回合0费、打出消耗，回合后费用恢复但消耗仍在。永久牌组不变。
- 复制牌在为什么呀生效时入场仍0费；同回合8次重抽后，显示费用和实际支付仍均为0，回合结束恢复当前本场随机费用。
- _Karasu_ 基础/升级对两名敌人各造成12/16伤害；从抽牌堆取原有实体，继承升级及费用。仅有1张时全取，0张时不生成或洗牌；相同种子结果一致，不重复取同一实体；满手时沿用原版溢出弃牌。
- 犹如幻翳基础/升级以此前3/2次触发为门槛，自身这次不能凑门槛。分别8/12伤害，条件满足给予1层无实体，无论是否满足都消耗。
- 要乐奈基础与升级0费、不消耗。此前3次触发时攻击4段，合计24/32；自己回合开始清零后恢复1段，当前牌这次触发不计入本次攻击。
- 回归古神清空、形态免伤与到期、直接击杀、群伤实际扣血、伙伴强化/入狱/救援、整次攻击保护、累计扣血上限、眩晕、随机费用、自动出牌与变身摆动恢复。

## 构建、安装和边界

构建成功，0错误。最后完整构建有2条NU1900警告，原因是NuGet漏洞元数据查询不可达；代码编译及PCK导出成功。DLL、PCK、JSON已安装到本机 `mods/OTTO`，与分发目录逐字节相同；`OTTO-v0.5.0.zip`只包含这3个文件，内容与安装文件一致，完整性检查通过。校验值见 `confirmed-cards-package-sha256.json`，旧版安装备份见其中记录的工作区路径。

验证在独立游戏副本和内存战斗中进行，Steam初始化关闭，测试使用独立的OTTOTestCards用户目录。没有读取或继续正式冒险，也没有向正式游戏安装测试插件。游戏资源副本只改变测试用户目录名称，原游戏PCK未修改。没有自动完整通关或进行多机联机测试；原版卡图仍作为新牌占位图。

无界面场景未创建实战屏幕震动目标，日志中的Missing screenShake target及退出时资源清理提示属于测试场景限制。真实手牌归还测试验证了容器顺序，没有进行完整战斗画面的人工点击验收。

原始工作簿只读；12张确认设计与读取时SHA-256保存在 `cards-source-confirmed-2026-09-30.json`，未向工作簿写入任何修改。
